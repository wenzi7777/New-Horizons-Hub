# v0.6.0

## 大回應分頁轉發

搭配 New Horizons OS v1.11.0：裝置的回應超過一個 ESP-NOW frame（7680 B）時會分頁。

- Hub 收到第 0 頁後，一頁一頁向裝置要下一頁（`result_page`），每頁以 `device_result_chunk` 轉給 Backend 重組。
- Hub 一次只保留一頁，不增加記憶體壓力。
- 先送出下一頁的請求再轉發這一頁，兩件事同時進行。
- 頁的請求不等 ack，500 ms 沒收到就重送；30 次後回 `result_page_timeout`。
- 修正：控制 frame 的就緒旗標改在 callback 之前清除，否則在轉發期間抵達的下一頁會被丟掉。

## 其他修正

- **校正擷取逾時**：送出後等回應的上限原本固定 10 秒，擷取時間設長就一定逾時；現在會加上指令的 `duration_ms`。
- **指令過大**：超過 3840 B 的指令原本要等 15 秒才回 `command_delivery_timeout`；現在立刻回 `command_too_large`。
- **關閉 WiFi 省電**：Arduino 在 S3 上預設是 modem sleep，射頻關閉時會漏收 ESP-NOW 封包。開機時序列埠印出 `wifi_power_save before= after=`。

## 驗證

- **尚未實機驗證**。

## 相容性

- 舊版裝置韌體（不分頁）照常運作。
- 舊版 Backend 不認得 `device_result_chunk`，大回應會逾時（和以前一樣拿不到）；小回應不受影響。建議 Backend 先更新到 Desktop v0.18.0。
