# v0.12.0

**When a new version is out, the Hub enters "update required" just like the Gateway: paired devices keep relaying as usual, but settings changes and pairing new devices are locked. Once no device has been online for a full minute, it updates and restarts automatically.**

## Learning about the latest version

- When the Hub connects, the Backend tells it the latest version on its channel (stable / beta) in `gateway_hello_ack`. The Hub's hello now carries `update_channel`.
- A Hub that stays connected asks again every 30 minutes with `hub_version_check`, so it does not have to restart to learn about a new version.
- If the Backend is an older version that does not support these messages, the Hub reads the manifest itself every 6 hours while idle.
- The Desktop's "Check for updates" result also updates this state; switching the update channel clears the old channel's state and checks the new channel right away.

## While an update is required

- **Paired devices keep relaying data and commands as usual.**
- **Locked**:
  - Connection settings (`set_config`) reply `update_required`.
  - Pairing requests from new devices are ignored.
- **Not locked**: check for updates, update now, switch update channel, factory reset.
- New pairing is not locked for the first 60 seconds after boot: the paired list lives only in memory, so devices must be able to pair back after the Hub restarts.
- If a paired device is offline for more than 30 seconds, its slot in the list is released; when it comes back it is treated as a new device and cannot pair until the Hub has updated.
- The `update` block of `gateway_status` gains `required_update`, `latest_hub_version` and `auto_apply` (`waiting_for_idle` / `retry_later`).

## Automatic update when idle

- The update starts only after 60 seconds with no device online and no device OTA being relayed, so recordings are never interrupted.
- If the automatic update fails, it retries in about 30 minutes; meanwhile you can still update manually from the Desktop.
- The automatic update at boot is unchanged.

## Compatibility

- With Desktop v1.1.0 the Hub knows the latest version as soon as it connects; with older Desktops it relies on its own checks while idle.
- The protocol with devices is unchanged; device firmware v1.17.0 is recommended.
- Not yet verified on hardware.
