# v0.7.0

## 為配對裝置提供時間

搭配 New Horizons OS v1.12.0：ESP-NOW（Direct）模式的裝置改向 Hub 對時。在這之前，這類裝置完全拿不到真實時間。

- **Hub 自己的時鐘（`HubClock`）**：
  - WiFi 連上後就用 NTP（`pool.ntp.org`，備用 `time.google.com`）對時，每 10 分鐘重新校正。ESP-IDF 預設是 3 小時；Hub 底下的裝置會繼承 Hub 的漂移，所以縮短。
  - 開機 2 分鐘後 NTP 仍沒有回應時，改用 Desktop 後端的時間：送 `ping`，從 `pong` 的 `server_time_ms` 計算，並扣掉來回時間的一半。需要 Desktop v0.19.0 的後端。
  - 校正不跳時間：100 ms 以內的誤差慢慢追上，超過才直接跳。
- **回應裝置的對時請求**：收到 TIME_REQ（`0xE8`，12 B）時記下到達時刻，在主迴圈回覆 TIME_RESP（`0xE9`，32 B），內含收到與送出的時間。裝置會扣掉 Hub 的處理時間與來回延遲。
- **`gateway_status`** 新增 `clock` 區塊：來源、是否同步、同步時長、誤差，以及 NTP／後端兩個來源的統計。Desktop 的 Hub 管理視窗會顯示。
- **新的 Hub 指令 `clock_sync`**：重新啟動 NTP，並立刻向後端對時一次。

## 共用檔

新增 `ClockCore`、`EspNowTimeWire`，與裝置韌體逐位元組相同。`tests_native/run_time_service_contract.sh` 會檢查兩邊是否一致，並跑一次完整的對時計算。

## 相容性

- 舊版裝置韌體不會送對時請求，行為不變。
- 舊版後端的 `pong` 沒有 `server_time_ms`，Hub 只用 NTP。
