# v0.12.0

**有新版時，Hub 會像 Gateway 一樣進入「需要更新」：已配對的設備照常轉發，但設定修改與新設備配對會被鎖住；沒有設備在線滿 1 分鐘，就自動更新並重新啟動。**

## 得知最新版本

- 連上 Backend 時，Backend 會在 `gateway_hello_ack` 裡告訴 Hub 它所在通道（stable / beta）的最新版本。Hub 的 hello 現在會帶 `update_channel`。
- 一直連著不斷線的 Hub，每 30 分鐘會用 `hub_version_check` 再問一次，不必等重開才知道有新版。
- Backend 是不支援這些訊息的舊版時，Hub 會在閒置時每 6 小時自己讀一次 manifest。
- Desktop 的「檢查更新」結果也會更新這個狀態；切換更新通道時，舊通道的狀態會清掉，並立刻用新通道重新查詢。

## 需要更新時

- **已配對的設備照常轉發資料與指令**。
- **鎖住**：
  - 連線設定（`set_config`）會回 `update_required`。
  - 新設備的配對請求會被忽略。
- **不鎖**：檢查更新、立即更新、切換更新通道、恢復原廠設定。
- 開機後 60 秒內不鎖新配對：配對名單只存在記憶體，Hub 重開後原本的設備要能重新配對回來。
- 已配對的設備若離線超過 30 秒，它在名單裡的位置會被釋放，回來時會被當成新設備而無法配對，直到 Hub 更新完成。
- `gateway_status` 的 `update` 區塊多了 `required_update`、`latest_hub_version`、`auto_apply`（`waiting_for_idle` / `retry_later`）。

## 閒置時自動更新

- 沒有設備在線、也沒有在幫設備做 OTA 轉送，持續 60 秒後才開始更新，不會打斷錄製。
- 自動更新失敗時，約 30 分鐘後再試；期間仍可以從 Desktop 手動更新。
- 開機時的自動更新照舊。

## 相容性

- 搭配 Desktop v1.1.0 時，Hub 一連上就知道最新版本；搭配舊版 Desktop 時，靠閒置時的自行檢查。
- 與裝置之間的協定沒變，建議搭配裝置韌體 v1.17.0。
- 尚未實機驗證。
